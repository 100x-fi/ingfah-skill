# ผลลัพธ์แบบ Metadata (JSON)

> ให้ระบบสรุปข้อมูลจากบทสนทนาออกมาเป็น JSON ตามโครงสร้างที่คุณกำหนด
>
> Source: https://docs.ingfah.ai/guides/inbound-outbound/outcome-metadata/

นอกจาก [ผลลัพธ์แบบสถานะ](/guides/inbound-outbound/call-outcome-setup/) ที่จำแนกว่าการสนทนาจบลงอย่างไร คุณยังให้ระบบดึง **ข้อมูลรายละเอียด** ออกจากบทสนทนามาเป็น JSON ได้ด้วย เช่น ชื่อลูกค้า วันที่ลูกค้านัดจะชำระเงิน จำนวนเงินที่รับปาก หรือเหตุผลที่ปฏิเสธ

ข้อมูลชุดนี้เรียกว่า **ผลลัพธ์แบบ metadata (JSON)** ตั้งค่าแยกตามทีม AI Agent และเหมาะกับการส่งต่อเข้าระบบหลังบ้านของคุณ เพราะได้โครงสร้างข้อมูลที่แน่นอน ไม่ใช่ข้อความอิสระ

## ตั้งค่าที่ไหน

1. ไปที่ **AI Agent** → **ทีม AI Agent** แล้วเปิดทีมที่ต้องการ
2. เลื่อนไปที่หัวข้อ **ตั้งค่าผลลัพธ์หลังวางสาย**
3. เลือกแท็บ **ผลลัพธ์แบบ metadata (JSON)**
4. หากทีมยังไม่เคยตั้งค่า กด **ตั้งค่า** เพื่อเริ่ม

แต่ละแท็บทำงานแยกกัน — ผลลัพธ์แบบสถานะ, ผลลัพธ์แบบ metadata และสรุปบทสนทนา (ซึ่งระบบทำให้อัตโนมัติทุกสายอยู่แล้ว)

## เปิด / ปิดการใช้งาน

แท็บนี้มีสวิตช์ **เปิด / ปิด** หากปิดไว้ ระบบจะไม่สรุปข้อมูลเป็น JSON ให้ แต่การตั้งค่าที่บันทึกไว้จะยังอยู่ กลับมาเปิดใหม่ได้ภายหลัง

หากต้องการล้างการตั้งค่าทั้งหมด ให้กด **ลบการตั้งค่า**

## ตั้งค่าชุดข้อมูล

| ช่อง | รายละเอียด |
|------|-----------|
| **ชื่อชุดข้อมูล** | ชื่อของ schema ใช้ได้เฉพาะ a-z, A-Z, 0-9, `_` และยาวไม่เกิน 64 ตัวอักษร |
| **คำอธิบาย** | อธิบายว่าชุดข้อมูลนี้เก็บอะไร |
| **กำหนด JSON Schema** | รายการ Key ที่ต้องการดึงจากบทสนทนา |
| **บังคับให้ JSON มีทุก field เสมอ** (strict) | ระบบจะคืนครบทุก Key ทุกครั้ง Key ที่ระบุค่าจากบทสนทนาไม่ได้จะเป็น `null` หรือค่า default |

### ประเภทข้อมูลของแต่ละ Key

| ประเภท | ใช้เมื่อ | ตั้งค่าเพิ่มได้ |
|--------|---------|------------------|
| String | ข้อความ เช่น ชื่อลูกค้า | — |
| Integer | จำนวนเต็ม | ค่าต่ำสุด / ค่าสูงสุด |
| Number | ตัวเลขที่มีทศนิยมได้ เช่น ยอดเงิน | ค่าต่ำสุด / ค่าสูงสุด |
| Boolean | ใช่ หรือ ไม่ใช่ เช่น ลูกค้ารับปากจะจ่ายหรือไม่ | — |
| Enum | ต้องเป็นหนึ่งในตัวเลือกที่กำหนด เช่น `ชำระแล้ว`, `ขอผ่อน`, `ปฏิเสธ` | รายการตัวเลือก (อย่างน้อย 1 ค่า) |
| Array | ข้อมูลหลายค่า เช่น รายการสินค้าที่ลูกค้าถาม | ประเภทของ item และความยาวสูงสุด |
| Object | กลุ่มข้อมูลย่อย เช่น ที่อยู่ที่มีหลายส่วน | เพิ่ม **Nested Key** ข้างในได้ |

แต่ละ Key กำหนด **ชื่อ Key**, **คำอธิบาย** และเลือกได้ว่า **จำเป็น** หรือไม่

:::tip[คำอธิบายคือสิ่งที่ AI ใช้ตัดสินใจ]
เขียนคำอธิบายของแต่ละ Key ให้ชัดว่าต้องการข้อมูลอะไรและรูปแบบไหน เช่น `วันที่ลูกค้ารับปากว่าจะชำระ รูปแบบ YYYY-MM-DD` จะได้ข้อมูลตรงกว่าการเขียนว่า `วันที่จ่าย`
:::

## คำสั่งเพิ่มเติม

ช่อง **คำสั่ง** ใช้ใส่กติกาเพิ่มเติมให้ AI จัดข้อมูลลง schema ได้แม่นยำขึ้น เช่น

> หากไม่มีการเอ่ยชื่อลูกค้า ให้ใส่ customer_name = 'ลูกค้าใหม่'

เปิดหรือปิดการใช้คำสั่งนี้ได้แยกจากตัว schema

## แบบฟอร์ม หรือ Raw JSON

สลับมุมมองได้ 2 แบบ

- **แบบฟอร์ม** — เพิ่ม/ลบ Key ทีละรายการ เหมาะกับคนที่ไม่ถนัด JSON
- **Raw JSON** — วาง `json_schema` ทั้งก้อนเข้ามาโดยตรง ในรูปแบบ `{ "name": "...", "strict": true, "schema": { ... } }`

:::caution[สลับกลับเป็นแบบฟอร์มไม่ได้ถ้า JSON ผิด]
หากแก้ใน Raw JSON แล้วรูปแบบไม่ถูกต้อง ระบบจะไม่ยอมให้สลับกลับไปโหมดแบบฟอร์มจนกว่าจะแก้ JSON ให้ถูก
:::

## ข้อผิดพลาดที่พบบ่อย

| ข้อความ | สาเหตุ |
|---------|--------|
| รูปแบบ JSON ไม่ถูกต้อง | วงเล็บปีกกาหรือลูกน้ำไม่ครบ |
| มี key ที่ชื่อซ้ำกัน | ชื่อ Key ซ้ำในระดับเดียวกัน |
| ชื่อ key ใช้ได้เฉพาะ ก-ฮ, a-z, A-Z, 0-9, เว้นวรรค และ _ | ชื่อ Key มีอักขระที่ไม่รองรับ |
| มี key ประเภท array ที่ไม่ได้ระบุประเภท datatype | Array ยังไม่ได้เลือกประเภทของ item |
| มี key เป็น enum ที่ยังไม่มีตัวเลือก | Enum ต้องมีตัวเลือกอย่างน้อย 1 ค่า |
| ค่า maximum ต้องมากกว่า minimum | ใส่ช่วงตัวเลขสลับกัน |
| ใช้ strict mode อยู่ แต่ key ยังไม่อยู่ใน required | เปิด strict แล้วต้องกำหนดให้ทุก Key เป็น required |
| มี keyword ที่ระบบไม่รองรับ | ระบบไม่รองรับ `anyOf`, `oneOf`, `$ref` และ `patternProperties` |

## ดูผลลัพธ์ที่ได้

หลังจบการสนทนา ผลลัพธ์ JSON จะแสดงในคอลัมน์ **Metadata** ของหน้า [สายทั้งหมด](/guides/inbound-outbound/all-calls/) กดเพื่อเปิดดูข้อมูลเป็น JSON ได้

:::note[ปรับ schema แล้วมีผลกับสายใหม่เท่านั้น]
การแก้ไข schema ไม่ย้อนกลับไปประมวลผลสายที่จบไปแล้ว ผลลัพธ์รูปแบบใหม่จะเริ่มมีผลกับการสนทนาที่เกิดขึ้นหลังบันทึกการตั้งค่า
:::
